# Поступова міграція до scenario-first SDD

Мігруй існуючу feature, коли змінюється її поведінка або користувач окремо
дозволив повну міграцію документації.

## Новий або змінений scope

1. Збережи всі завершені ID, task-файли та verification history.
2. Додай `R-*` і `SC-*` для нової/зміненої поведінки. Незмінені сценарії
   отримують ID лише якщо потрібні для залежностей або regression.
3. Додай `traceability.md` для зміненого scope.
4. Нові implementation/verification responsibilities отримують `TS-*`, shared
   prerequisites — `EN-*`.
5. Старі великі phase-файли залиш як історичні orchestration records. Нову
   реалізацію винеси в малі task-файли.
6. Для нової testable behavior застосуй Red → Green → Refactor → Regression.

## Feature у роботі

Не перенумеровуй активні чи завершені legacy tasks. Заверши вже розпочату
відповідальність, а новий формат введи на найближчому безпечному planning
checkpoint. Посилайся на старе evidence замість його копіювання.

## Повна міграція

Лише за явно дозволеної повної міграції признач `R-*`/`SC-*` усьому
актуальному scope. У `TS-*`/`EN-*` перетворюй незавершену роботу; завершені
файли залиш пов'язаною історією.

Міграція завершена, коли змінена поведінка має стабільні ID, task graph і
traceability, а scope та історичні докази не були тихо змінені.
