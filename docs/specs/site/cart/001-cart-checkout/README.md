# 001 — Корзина и быстрое оформление заказа Kedr

- **Клиент:** публичный Next.js Site, `apps/site`; checkout — приватный служебный маршрут публичного приложения.
- **Домен:** `cart`, шаг 5 миграции; интеграция с покупкой товара завершает границу 4B.
- **Статус SDD:** реализована 2026-11-04; автоматические и source-проверки выполнены; архитектурный аудит с исправлениями AF-003–006 завершён, выпускные проверки отдельно.
- **Владелец:** frontend Kedr. Изменения KedrStore, Admin и старого Angular storefront не входят.
- **Создано / обновлено:** 2026-11-03 / 2026-11-04.

Покупатель добавляет доступную фурнитуру с известной ценой в общую корзину, проверяет состав в панели из шапки или на checkout и отправляет быстрый заказ без регистрации. Обязательны имя и телефон. Успех подтверждается фактическим идентификатором заказа; условия доставки и оплаты уточняет менеджер.

## Принятые решения

Пользователь принял концепт, поручил подготовить SDD и 2026-11-04 прямо разрешил реализацию функционала. На широком экране **два блока рядом**: товары слева, контакты и итог справа. Принятая после обратной связи граница — **720 px ширины области checkout**; ниже — одна колонка. Общий SiteShell сохраняет собственные проектные breakpoints. [Сохранённый концепт](design/concept.html) скопирован без изменений; [нормативный визуальный дизайн](design/visual.md) описывает перенос на реальные данные.

Маршрут остаётся `/{locale}/checkout`, локали `uk` и `ru`. Из шапки открывается drawer; его переход к оформлению ведёт на этот маршрут. Отдельные `/cart`, success URL, полный checkout с адресом, онлайн-оплата и кабинет не добавляются.

Логика сверена со [старой корзиной](../../../../features/storefront/catalog/cart.md), [старым checkout](../../../../features/storefront/catalog/checkout.md) и [контрактом заказа](../../../../contracts/openapi/catalog/orders.openapi.yaml). Общий диапазон количества 1–1000 соответствует API и принятому концепту; старый checkout ограничивал ввод 99. Остальные улучшения касаются целостности состояния и обработки ошибок, а не новых возможностей backend.

## Реализация и проверки

Созданы пять Nx-библиотек cart, единый document owner и совместимое хранение cart_v1. CartRuntime в locale layout связывает покупку товара, обе кнопки шапки, один drawer и checkout. Серверный callback карточки исполняется до client boundary; UI получает сериализуемый descriptor. Product EN-002 / TS-005 закрыты через cart TS-009 без feature→feature imports.

Заказ отправляется отдельной anonymous Server Action → cart/data-access → фиксированный no-store POST /api/orders. Контакты валидируются на клиенте и сервере. Pending блокирует повтор и изменения; validation/conflict/uncertain сохраняют состав и draft. Только корректный UUID подтверждает успех и очистку; receipt остаётся видимым при ошибке удаления storage.

EN-001–003 и TS-001–010 выполнены в коде с unit/component/server/source evidence. Последующий архитектурный аудит выделил DOM focus adapter, перенёс product URL policy в feature и усилил Nx/ESLint границы; AF-003–006 verified. [Результаты и точные команды](verification/implementation.md), [локальное ревью границ](code-audit/audit.md), [фактическая карточка](../../../../features/site/cart.md). У SC-023/024 подтверждены структура, tokens и локали; браузерное визуальное соответствие не проверялось.

## Ограничения готовности

- Production build, HTTP, browser/visual/manual, E2E, live order и deployment не запускались. Готовность к выпуску на хостинге этими проверками не заявляется.
- Без идемпотентности backend frontend предотвращает одновременные повторы в текущем документе; дубликаты между вкладками, после reload или после неопределённого результата не исключены.
- cart_v1 переносится только в том же origin. Контакты/операция/receipt хранятся в памяти документа и теряются при полной перезагрузке. При недоступном storage корзина работает в памяти.
