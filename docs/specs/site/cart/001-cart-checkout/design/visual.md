# Принятый визуальный дизайн

Нормативный перенос [принятого концепта](concept.html) в [действующую дизайн-систему Site](../../../../../standards/site/design-system.md). Прототип показывает демонстрационные товары, цены и UUID; он не является реализацией API или источником product facts.

## Композиция checkout

1. Существующий SiteShell целиком: навигация, каталог, поиск, кабинет, язык, тема, основной и компактный header, footer. Новый header для checkout не создаётся.
2. Home breadcrumb, H1 «Оформлення замовлення» / «Оформление заказа», короткое описание быстрого заказа и ссылка продолжить покупки.
3. При ширине **области checkout от 720 px** — две колонки: слева более широкий состав заказа; справа контакты, стоимость товаров и отправка. Обе выровнены по верхней границе. Сетка ориентировочно `minmax(0,1.4fr) minmax(280px,1fr)`, gap 16–24 px.
4. Ниже 720 px — товары, информационный блок доставки/оплаты, контакты, итог и CTA последовательно. Граница относится к содержимому фичи, не заменяет breakpoints shell. Целевые ширины: 320, 390, 719, 720, 736, 1024, 1440 px.
5. При длинном названии/UUID текст переносится; цена/количество остаются читаемыми. При необходимости итог переносится внутри правой панели, а колонки остаются рядом на согласованной ширине.

Левая панель: название «Ваше замовлення», число разных товаров и единиц, фото/нейтральный fallback, название, подтверждённый код товара, цена за единицу, quantity, сумма строки и удаление. Отдельный SKU не выдумывается из неподтверждённого legacy ID. Внизу отдельное пояснение: доставку и оплату уточнит менеджер. Цена не называется окончательной суммой к оплате.

Правая панель: подписанные имя и телефон, inline errors, количество и стоимость товаров, доставка «Узгодимо окремо», основной CTA «Надіслати замовлення». Ссылки на существующие public offer/privacy/delivery pages берутся из локализованной навигации. Email, адрес, способ доставки, платёжные поля и новое обязательное согласие не добавляются.

## Drawer корзины

Правый controlled Sheet существующей UI-библиотеки, один на runtime. На телефоне занимает доступную ширину; на большом экране — компактная панель около 440–480 px. Строки и totals используют тот же owner, что checkout. Основной CTA «Оформити замовлення», вторичный — продолжить покупки/закрыть.

В рабочей реализации список прокручивается внутри доступной высоты Sheet, а итог и CTA остаются доступны; растяжение drawer на высоту всего документа из inline-концепта не переносится. Focus management, Escape, backdrop и возврат фокуса — существующий Radix Sheet. Закрытие панели не удаляет товары и не отправляет заказ.

## Состояния и взаимодействия

| Состояние                | Видимый результат                                                                                                        |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| Восстановление           | Нейтральный skeleton/status, без ложного empty и нулевого cart count                                                     |
| Непустая корзина         | Редактируемые строки, согласованные суммы в header/drawer/checkout                                                       |
| Пустая                   | Краткий текст и реальная ссылка в каталог; форма/submit отсутствуют                                                      |
| Некорректное количество  | Ввод требует исправления либо возвращается к последнему допустимому значению с сообщением; zero не удаляет строку неявно |
| Частичное восстановление | Понятное уведомление о пропущенных строках и явное подтверждение продолжения с восстановленными товарами                 |
| Ошибка поля              | Ошибка рядом с полем; введённое значение и состав сохраняются                                                            |
| Pending                  | «Надсилаємо…», защита click/Enter, поля/количество/удаление заблокированы                                                |
| 400 / 409                | Нормализованные ошибки, доступно исправление; без самостоятельного вывода об остатке/новой цене                          |
| Неопределённый результат | Заказ мог поступить; контакт менеджера перед повтором, без автоматического POST                                          |
| Успех                    | Фактический UUID, подтверждение, следующий контакт с менеджером; receipt не перекрывается empty state                    |
| Storage недоступен       | Корзина работает в текущей вкладке, ограничение сохранения объяснено                                                     |

## Тема, язык, доступность

Onest для интерфейса; JetBrains Mono только для SKU/UUID. Нейтральные light/dark tokens из `global.css`; border, поля и радиусы проекта. Primary CTA — ink/inverted; brand green — каталог, счётчик, небольшие состояния; обычный зелёный текст — `brand-text`. Реальные фото на нейтральном фоне, при отсутствии — category icon.

UK/RU copy типизирована; формы, ошибки и labels доступны в обеих локалях. Переключения не меняют числовые цены/количества и не стирают draft. Сохранённое название legacy товара не переводится выдуманным текстом. Длинный реальный title проверяется отдельно.

Keyboard labels, видимый focus, кнопки quantity/delete с названием товара, связанные ошибки через `aria-describedby`, `aria-invalid`, общий результат через live region. Touch targets около 44×44 px, editable text на телефоне не меньше 16 px. Нет действий только по hover; reduced motion у feedback/loading.

Дизайн проверяется в source/component tests. Browser/visual/manual matrix выполняется только после отдельного разрешения на конкретную проверку; автоматические проверки не выдаются за осмотр рендера.
