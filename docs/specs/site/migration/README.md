# Перенос витрины на Next.js: план миграции

**Статус:** шаг 1 (оболочка) сделан, остальные шаги — план. Каждый шаг — отдельный SDD в варианте `nextjs` с обязательным `design/seo.md` (скил `frontend-feature-spec`) и отдельный PR; слияние только с согласия владельца.
**Дата:** 2026-10-29.
**Связано:** [ADR-0001](../../../architecture/site/adr/0001-nextjs-public-site.md), [архитектура сайта](../../../architecture/site/README.md), [опись фич и SEO-анализ](feature-inventory.md), [дизайн-система](../../../standards/site/design-system.md), [идея и макет](../../../ideas/storefront-nextjs/README.md).

## Цель

Заменить Angular-витрину `apps/storefront` новым сайтом `apps/site` (Next.js App Router, shadcn/ui, Tailwind CSS v4) с новым дизайном и сильным SEO, не потеряв текущие адреса и позиции в поиске. Бизнес: только продажа дверной фурнитуры, опт с возможностью розничного заказа.

## Правила для всех шагов

1. Адреса страниц не меняются: `/uk|ru/catalog/{slug}/products`, `/uk|ru/catalog/product/{slug}` и т. д. Если адрес всё же меняется (статьи), добавляется 301 в карту редиректов.
2. Angular-витрина обслуживает домен до шага 9; новый сайт живёт на превью-домене с выключенной индексацией.
3. Новые проекты и компоненты создаются командами (`npx nx g @nx/react:library`, `npx shadcn@latest add`), не вручную.
4. Каждый шаг заканчивается аудитом изменённого кода (`frontend-code-audit`), разбиением больших файлов и группировкой папок.
5. На каждом шаге: тесты билдеров SEO, `curl`-проверка HTML (статус, title, canonical, hreflang, JSON-LD), строка в таблице URL-политики.
6. Данные только через `site-shared-api-client` и доменный `data-access`; сгенерированные типы не выходят из `data-access`.

## Решения владельца

- Хостинг — Cloudflare через OpenNext (2026-10-30).
- Кэш — современная модель Next.js: Cache Components (2026-10-30).
- Двери остаются в каталоге, скорее всего отдельной вкладкой; детали на шаге 3 (2026-10-30).
- Плоские адреса `/{locale}/catalog/{slug}`, `/{locale}/product/{slug}`, поиск `/{locale}/search?q=`, старые адреса — 308 (2026-10-30).
- Статьи хранятся в базе и редактируются в админке; нужна доработка KedrStore и админки к шагу 6 (2026-10-30).
- `[NEEDS CLARIFICATION: региональные страницы — 23 страницы с уникальным текстом или одна страница «Доставка по Україні»; решение отложено]`.
- Тексты категорий и описания товаров пишет владелец; код их только выводит.

## Риски

- Два сайта в одном репозитории до шага 9: общие данные (слаги категорий, контакты) могут разойтись. Снижение: категории из API на шаге 3, контакты в одном `COMPANY`.
- Падение позиций при переключении. Снижение: те же адреса, 301 для изменённых, sitemap, Search Console, переключение после аудита.
- Бедная карточка товара без полей от бэкенда. Снижение: начать задачи KedrStore параллельно с шагами 2–3.
