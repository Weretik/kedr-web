# Product details — архитектурный аудит и исправления

Дата: 2026-11-03. Объём: реализованный независимый этап4A — пять `libs/site/product/*`, три app entry и непосредственные границы catalog/model, core и shared API. Пользователь явно разрешил исправить найденные проблемы. Общая корзина EN-002/TS-005 остаётся отдельной blocked предпосылкой полной поставки.

Результат: **три подтверждённых finding, все verified** — один P2/medium и два P3/low. Открытых архитектурных finding в проверенном объёме нет. Это локальный аудит реализованной функции; другие приложения, визуальный/SEO аудит и общий поиск техдолга не выполнялись.

## 00. Базис и границы

Применены root/app AGENTS, [Site modules](../../../../../architecture/site/structure/modules.md), [frontend design и file-role map](../design/frontend.md), [API/data rules](../../../../../standards/shared/api-data-rules.md) и [testing rules](../../../../../standards/shared/testing-rules.md). Проверены реальные `project.json`, aliases/public barrels и [boundary policy](../../../../../../tools/architecture/project-boundary-rules.mjs). Числовые лимиты размера компонентов и правила организации Admin/Mobile не переносились на Site.

Установленный стек: Next16.4.3, React19.3.0, Nx24.0.3, Vitest5.0.5; Cache Components, typed GET, shadcn/Radix/Tailwind, Onest/Lucide. Новых зависимостей, aliases, разрешений графа или generated DTO изменений исправления не потребовали. Snapshot API сохранён.

## 02. Данные, API и состояние

Путь чтения: app → product/feature → server-only product/data-access → shared typed `siteApiGet` → generated operation; mapper возвращает `ProductDetails`/domain results. Current/moved/category-redirect/not-found/unavailable координирует feature; UI не разбирает HTTP response.

В `contracts/product.dto.ts` остались generated aliases и derived identity projection, в `contracts/product-redirect.parser.ts` — разбор неизвестного 404 body. Мапперы сохраняют domain normalization/identity/media/paging checks, loader — cache и исходы typed GET. Публичный barrel data-access не экспортирует DTO/parser/mapper. Это разделение ролей без изменения runtime policy.

Success cache — hours, failure/redirect — короткий профиль; ключи публичные, без cookies/session/cart. Полный index отделён от page transport и walker, ограничен 1000 страницами на locale, несогласованность получает один повтор. В компонентах нет второго API cache. Клиентское состояние ограничено выбором/отказами media, zoom и результатом clipboard. Предполагаемый overflow cache tag отклонён: slug tag уже обрезан до 200 символов, с префиксом — 213 при лимите256; код не менялся.

Consumer projection и registry теперь отражают Site detail/discovery: [public products contract](../../../../../contracts/catalog/public-products.md#site-product-details-and-discovery). OpenAPI regeneration для документационного расхождения не нужна. AF-003.

## 03–04. Split / keep и публичные контракты

| Область                                             | Решение | Причина и итоговый владелец                                                                                                                                     |
| --------------------------------------------------- | ------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity + category destination                     | split   | Identity отвечает за SSR name/SKU/stock/category label, feature/mapping — за catalog route policy. Required `categoryHref: string \| null` делает решение явным |
| Data-access generated aliases и raw redirect parser | move    | Два приватных production-файла `contracts/` отделены от loader и четырёх normalization mappers; ни одного публичного DTO export                                 |
| `gallery/` — 2 production-файла                     | keep    | Gallery владеет selection/failure/zoom, media — отображением одного URL/fallback. Состояние ресурса и SSR product facts не смешаны                              |
| `identity/` — 2 production-файла                    | keep    | Server identity и browser clipboard уже разделены; async feedback принадлежит отдельному client leaf                                                            |
| `purchase/` — 1 production-файл                     | keep    | Price/pack/action slot составляют один server panel; derived mode в model, cart API и storage отсутствуют                                                       |
| `service/` — 1 production-файл, 4 exports           | keep    | Согласованный статический блок условий/опта/помощи с общим dictionary/COMPANY, без независимого состояния, effect, запроса или workflow                         |
| `detail/` и feature mapping                         | keep    | View только компонует готовые props/секции; feature раздельно адаптирует category href и SEO input                                                              |
| Feature routing/crawling                            | keep    | Response decisions, language confirmation, seeds, entries и shard budgeting уже имеют отдельных владельцев; монолита app route нет                              |

`next/link` остаётся принятым декларативным rendering primitive Site. Сам импорт не трактуется как imperatively routed UI. URL policy категории удалена из UI; статические service destinations соответствуют согласованному дизайну. Пустых слоёв и файлов совместимости не добавлено.
