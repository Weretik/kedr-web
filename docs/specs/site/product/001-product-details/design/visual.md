# Нормативный визуальный дизайн

## Основание и статус

[HTML-концепт](concept.html) принят как визуальное направление 2026-11-03. SHA-256 сохранённой версии: `66D49539131FC3553CD0B4A201361A6137FE89A6B2F910F808778C53FA76C40E`. Источник изображения внутри концепта — реальная иллюстрация категории `apps/site/public/assets/categories/handles.jpg`; это не подтверждённая фотография SKU. В production использовать только photo/scheme товара или fallback.

Нормативные правила — [дизайн-система Site](../../../../../standards/site/design-system.md) и текущие токены [global.css](../../../../../../apps/site/src/app/global.css). Концепт не заменяет общую оболочку, не вводит новый дизайн-язык и не служит готовым React-кодом. Его внешнее подключение Google Fonts, inline styles, host Tweak, локальная корзина и демонстрационные переключатели в приложение не переносятся.

## Структура

1. Существующие Site header, catalog navigation и footer без дублирования на странице.
2. Хлебные крошки: главная → каталог → разрешённые категории → товар.
3. Первый экран: крупная галерея слева; справа артикул/copy, текст наличия, H1, ссылка категории, цена, упаковка, количество/главное действие.
4. Небольшой спокойный блок «Купуєте оптом?» со ссылкой на `/wholesale`, затем короткие ссылки условий.
5. Якорная навигация «Про товар / Доставка та оплата / Повернення та обмін». Это ссылки, все секции остаются видимыми, не скрытые Tabs.
6. Факты из API и краткий блок условий со ссылками на действующие страницы.
7. Помощь с выбором и реальный телефон менеджера из COMPANY.

Не добавлять пустое описание, бренд, цветовые swatches, рейтинги, промо-скидку, точные остатки, сроки отправки, произвольную гарантию и «З цим купують».

## Сетка и размеры

| Ширина viewport | Композиция                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------ |
| <1024 px        | одна колонка: галерея → идентичность/цена/покупка → сервис/факты; mobile header берётся из shell |
| ≥1024 px        | две колонки первого экрана примерно 52/48, gap 24–32 px; ниже две колонки фактов/условий         |
| ≥1440 px        | центрированный контент с проектным пределом 1440 px, без растягивания строк на весь монитор      |

Переход по viewport `lg=1024`, как у shell, не по ширине внутреннего контейнера после gutters. Gutters 16 px, от `lg` 24 px. Кнопки/поля radius 8 px, панели 10–16 px. Основное действие 44–48 px высотой, touch targets около 44 px. H1 26 px на узких/30–32 px на широких, без запрета переноса; цена 32–36 px. Длинные SKU/названия/категории переносятся, счётчик и действия не перекрывают их. Media canvas сохраняет размер при загрузке/fallback; схема и фото `object-contain`, без обрезки продукта. Не копировать CSS-crop демонстрационного category asset.

В реальном layout галерея явно занимает основную колонку, даже если миниатюры скрыты. Одна картинка не порождает фиктивные ракурсы; при единственном media thumbnail rail можно скрыть. Отдельная mobile sticky buy strip не включена: её нет в принятом концепте.

## Цвет, шрифты и изображения

| Назначение                    | Светлая / тёмная                                                                 |
| ----------------------------- | -------------------------------------------------------------------------------- |
| Фон / текст                   | `background` #FFFFFF / #0C0D0C; `foreground` #0F110F / #EDEFEA                   |
| Вторичная поверхность / текст | `muted` #F4F5F2 / #161815; `muted-foreground` #5C6459 / #9AA296                  |
| Граница                       | `border` #E3E6DF / #242823                                                       |
| Главное действие              | проектный `primary` и `primary-foreground`: ink в светлой, светлое в тёмной      |
| Фирменные акценты             | `brand` #3FA435; текст на нейтральном фоне только `brand-text` #2A7323 / #7DD06F |

В коде использовать токены, а не новые literal palettes. Onest через текущий `next/font`, JetBrains Mono только для SKU; Lucide stroke 1.75. Фото/схема на ровной светлой подложке в обеих темах. Не генерировать изображения продукта. Reduced motion сохраняется; короткое подтверждение покупки не заменяет читаемое status-сообщение.

## Главный блок и состояния

- Положительная retail price и inStock: количество от 1 и ink/light «У кошик». Доступность реального действия зависит от EN-002.
- Цена неизвестна: «Ціна за запитом» / «Цена по запросу», главное действие к менеджеру, без количества/покупки.
- Нет stock: сохранить числовую цену, если есть; главное действие «Уточнити наявність» / «Уточнить наличие».
- Нет stock и price: одновременно оба текста, действие уточняет наличие.
- Pack >0 отображается спокойной информационной строкой; не становится MOQ или шагом.
- Обработка добавления: исключить повторный submit; успех/ошибка текстом, ошибка не стирает количество.
- Media states независимы от purchase states, включая только схему и отказ одного URL.

## Ссылки и тексты

Условия ведут на `/{locale}/delivery-and-payment`, `/{locale}/returns-exchanges`; опт — `/{locale}/wholesale`; помощь — `/{locale}/contacts` и телефон из COMPANY. Точные тексты не дублируют юридические обещания: «Умови доставки та оплати», «Правила повернення та гарантії». Использовать текущие URL helpers и shell navigation, проверить актуальные route entries перед реализацией.

Все UI labels покрыты типизированным словарём UK/RU; товарное имя приходит из API. Скрытые aria-label и сообщения clipboard/ошибок также локализуются. Не переносить демонстрационный SKU, цену, pack или hardcoded контактные данные.

## Доступность и критерии точности

Видимый фокус, один H1, семантические breadcrumbs/факты, подписи icon buttons, текстовое наличие, polite status после операций. Галерея работает кнопками с выбранным состоянием; увеличение внутри media stage, без нового модального потока. Clipboard failure не сопровождается ложным «Скопировано». Якоря учитывают текущую sticky-шапку через scroll margin. Проверяемые размеры: 320, 390, 768, 1024, 1440 px, обе темы, обе локали и 200% текст.

Проверки стилей/семантики и focused component tests обязательны в соответствующих TS. Browser/visual/manual checks выполняются только после отдельного вопроса и прямого разрешения по правилам репозитория; принятие SDD само по себе их не запускает.
