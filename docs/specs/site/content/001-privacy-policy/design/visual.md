# Принятый визуальный контракт

Концепт принят пользователем 2026-11-03. [PNG](privacy-concept.png) и [approval/provenance](privacy-concept.png.json) — источник композиции. [Дизайн-система site](../../../../../standards/site/design-system.md) и текущий SiteShell — источник точных tokens и оболочки. PNG не становится содержимым страницы и не используется как screenshot-plate.

## Структура

Desktop: крошки → H1 и вступление → summary → сетка «оглавление + полная политика» → контакт и ссылка на оферту → существующий footer.

Phone/tablet: крошки → H1 и вступление → закрытое раскрывающееся оглавление → summary → полный документ → контакт и ссылка на оферту → существующий footer. Смысловой порядок восьми разделов не меняется.

| Ширина          | Наблюдаемая компоновка                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------------------------- |
| 320–639 px      | Один столбец; summary тремя строками; TOC disclosure; H1/email переносятся                                 |
| 640–1023 px     | TOC disclosure; summary в трёх колонках при достаточной ширине; текст остаётся читаемым                    |
| от 1024 px (lg) | Sidebar около 16rem, промежуток около 2rem, текст min-width:0 с мерой до 75ch; TOC sticky под category bar |
| 1440 px и шире  | Сохраняется общий shell cap 1440 px и существующие поля, без растягивания строки политики                  |

Оглавление desktop имеет top offset 5rem и ограниченную viewport-высоту с внутренней прокруткой для низкого экрана. Заголовки-якоря наследуют консервативный scroll-mt-48 ближайшего returns pattern. Существующий shell остаётся целым: все его ссылки, контакты, категории, язык, тема и четыре группы footer.

## Типографика и поверхности

Onest; H1 и ритм как у текущего returns header. Основной текст порядка text-base с достаточным line-height. Полные разделы не превращаются в карточки: H2, абзацы, списки и тонкие разделители.

Цвета только из существующих variables: background/foreground, muted, border, brand/brand-text, primary/primary-foreground. Светлая тема белая, тёмная почти чёрная. Зелёные body links используют brand-text; декоративные Lucide-иконки stroke 1.75. Кнопка email использует primary, в тёмной теме — светлая с тёмным текстом. Радиусы существующие: поля/кнопки 8 px, спокойные панели 10–16 px.

## Состояния и взаимодействия

- Mobile TOC закрыт по умолчанию; native summary раскрывается мышью, touch, Enter/Space. Выбор ссылки не требует программного закрытия.
- Desktop TOC видим; native fragment navigation, back/forward и прямой hash.
- Подсветка означает выбранный URL fragment. Вне fragment допустим начальный акцент первого пункта, без ложного статического aria-current. Ручной scroll не меняет выбранный пункт: scrollspy не входит в scope.
- CSS :target / :has оформляет выбор. При отсутствии :has остаются рабочие ссылки и видимый focus; функциональность от CSS-подсветки не зависит.
- В DOM могут быть две адаптивные версии TOC, но скрытая использует display:none; id элементов уникальны, policy sections не дублируются.
- Поддерживаются обе темы в обеих локалях. Четыре изображения не связывают uk только со светлой темой.
- Нет smooth scroll, animation reveal, loading skeleton, формы запроса или нового tracking.
