## Architecture baseline — checked 2026-11-03

Existing projects are `site-content-model`, `site-content-ui`, `site-content-seo` and `site-content-feature`; they carry `scope:site`, `domain:content` and respectively `type:model/ui/util/feature`. Their aliases and public index files already exist. All four targets were resolved with the installed Nx CLI. Vitest configs and the Nx `@nx/vitest` plugin expose `vite:test`; typecheck/lint are existing inferred targets. No generator, package or new target is needed.

The source contract is static and independent of the article data-access project. Actual route composition is app → content feature/SEO; feature → content UI/model and allowed core APIs; UI → model, core config/i18n and shared UI. Content SEO may use only core config/i18n/SEO under `tools/architecture/project-boundary-rules.mjs`; do not import content/model or UI into it. No cross-domain flow is added. Shared indexes and sitemap currently contain other ongoing work and receive additive edits only.

Version baseline from package-lock: Next 16.4.3, React 19.3.0, Tailwind 4.3.3, lucide-react 1.66.0. Existing shadcn/ui Button/cn and native details/summary are sufficient. No new data stack or state library. No confirmed in-scope systemic AF finding or shared EN prerequisite was found; this was a bounded baseline check, not a full code audit.

## Composition and state

Reuse SiteShell for skip link, header, main and footer. Its current header condenses on desktop; phones retain the full sticky header. Page section scroll offsets and desktop rail top must accommodate this behavior; use the nearby content-page scroll-margin conventions, conservative offsets and a focused header-offset source check. Do not change header behavior.

Document and contact are Server Components. Only current-section navigation and browser print are small client leaves. The contents leaf receives anchor descriptors/labels only, renders server HTML with real links, uses native details on narrow screens and enhances desktop current-item state after hydration. It handles initial hash/hash changes and section observation, cleans up listeners/observers and does not steal focus. Without the observer, links remain functional. Printing stays in its own leaf and never imports legal copy.

The default reading surface has no API loading, empty, permission or transport-error state. Existing locale 404 behavior remains. Contents closed/open, current section, keyboard focus and print readiness are the meaningful states. No personal state, network request, tracking, local storage or session dependency is added.

## Print isolation and verification

Scope every print rule to a visible public-offer page root; app-router CSS and hidden Activity page trees can both remain after navigation. Exclude hidden roots/ancestors, including React Activity inline display:none, before matching the root. Any shell-hiding selector must require that root (for example a body selector containing the local page marker), never a bare global print `header/footer` rule. Restore readable black-on-white text even when the screen theme is dark. Keep each paragraph together where feasible and keep headings with following text; do not apply unbreakable pagination to the whole document.

Focused component/unit tests prove source integrity, navigation, print invocation and SEO. Styling and print layout receive bounded source review; this does not prove actual browser layout or printer pagination. Follow the repository's separate-permission rule before any browser/manual/visual/print-preview/build check.

## Implemented structure comparison

The planned file roles were implemented within the existing four content libraries. Two small client leaves handle contents and print; full copy remains server-rendered. The actual tree and focused commands are in [the feature card](../../../../../features/site/public-offer.md). No new project, data stack, public API operation, alias or cross-domain dependency was needed. Print CSS uses the route marker and passed the installed Next pure/scope transforms.

The final source check against installed Next layout-router revealed retained hidden Activity trees. A focused CSS-selector regression was added at `libs/site/content/ui/src/lib/public-offer/public-offer-print-styles.spec.ts`; the final print guard excludes those trees without changing the document or shared shell. The longer CSS remains one cohesive page-print responsibility.

## Audit refinement: DOM ownership

The client Toc now passes its own local ref into the lifecycle hook. The hook resolves targets under the nearest `data-public-offer` and `data-offer-document` root, so retained sibling pages cannot supply matching IDs. Rendering/lifecycle remain separate, and no additional wrapper, public prop, server/client boundary or dependency is added.
