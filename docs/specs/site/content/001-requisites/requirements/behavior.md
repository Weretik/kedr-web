# Правила и сценарии

Статус: реализовано локально; достаточные автоматизированные/source evidence отражены в задачах. SC-012 ограничен внешним EN-002; реальные HTTP/browser проверки не выполнялись. Технические владельцы находятся в [frontend](../design/frontend.md), команды — в задачах.

## Правила

| ID    | Продуктовое правило                                                                                                                                                                                                      |
| ----- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| R-001 | Страница доступна по прежним адресам /uk/requisites и /ru/requisites; язык не меняется принудительно.                                                                                                                    |
| R-002 | Публикуются подтверждённые сведения именно об администрации сайта. Код, выписка, IBAN и МФО сохраняют все символы; сведения не объявляются реквизитами продавца любого заказа.                                           |
| R-003 | Все интерфейсные подписи и пояснения доступны на UK/RU. Официальное имя и числовые идентификаторы не переводятся и не изменяются при переключении языка.                                                                 |
| R-004 | Заголовок, сведения, пояснения и обычные ссылки доступны в исходном содержимом страницы до запуска интерактивных действий.                                                                                               |
| R-005 | Страница сохраняет существующие светлую/тёмную темы и каркас. На широком экране две панели рядом; на узком — последовательность принятого концепта без горизонтальной прокрутки.                                         |
| R-006 | Якоря ведут к администрации, банковским данным и пояснению об оплате. Все действия доступны с клавиатуры и имеют понятные названия.                                                                                      |
| R-007 | Отдельное действие IBAN копирует только точное исходное значение без визуальных пробелов/переносов.                                                                                                                      |
| R-008 | Действие «скопировать все реквизиты» копирует наименование, код, выписку, IBAN, банк и МФО с подписями текущего языка в устойчивом порядке.                                                                              |
| R-009 | Каждая операция копирования показывает ожидание, результат и понятный fallback. Повторное нажатие во время ожидания не запускает вторую операцию; после ошибки можно повторить. Ошибка не вызывает звонок или навигацию. |
| R-010 | Пояснение предлагает согласовать с менеджером наличие, окончательную сумму и реквизиты конкретного заказа. Контактное действие использует актуальный телефон сайта.                                                      |
| R-011 | Ссылки на доставку/оплату, оферту и политику ведут к соответствующему материалу на текущем языке. Публикация ссылок на оферту/политику зависит от готовности этих страниц.                                               |
| R-012 | Каждая языковая страница имеет свой title/description/canonical, взаимные языковые альтернативы и текущую политику индексации окружения.                                                                                 |
| R-013 | Структурированные хлебные крошки повторяют видимый путь «Главная → Реквизиты». Дополнительные банковские или налоговые утверждения не появляются в структурированных данных.                                             |
| R-014 | Оба канонических адреса включаются в общий sitemap по действующей политике сайта, без вымышленных дат и удаления соседних страниц.                                                                                       |
| R-015 | Неподдерживаемый языковой адрес не получает обычную страницу реквизитов с успешным статусом или молчаливый перевод на другой язык.                                                                                       |

## Наблюдаемые сценарии

### SC-001 — адрес и содержимое до интерактивности

**Covers:** R-001, R-004. **Уровень:** server integration; реальный HTTP — отдельная разрешённая проверка.

**Given** посетитель открывает украинский или русский адрес реквизитов. **When** получает начальное содержимое без выполнения интерактивных действий. **Then** видит один основной заголовок, данные администрации, банковские сведения, пояснение об оплате и контакт; адрес сохраняется.

### SC-002 — точность официальных данных

**Covers:** R-002. **Уровень:** подтверждение источника + server integration; prerequisite EN-001.

**Given** владелец подтвердил актуальный набор реквизитов администрации. **When** посетитель читает страницу. **Then** имя и каждый идентификатор совпадают с подтверждённым источником, а текст не объявляет этот набор универсальным получателем всех заказов.

### SC-003 — язык и официальное имя

**Covers:** R-003. **Уровень:** component + server integration.

**Given** доступны обе языковые версии. **When** посетитель меняет язык. **Then** остаётся на странице реквизитов, видит переведённые подписи и пояснения, а официальное имя и идентификаторы сохраняются.

### SC-004 — темы и узкий экран

**Covers:** R-005. **Уровень:** component + проверка theme/breakpoint wiring по исходникам; browser geometry отдельно.

**Given** посетитель использует любую поддерживаемую тему и ширину экрана. **When** читает страницу. **Then** сведения и действия читаемы; панели переходят из двух колонок в одну, длинное имя/IBAN не расширяют страницу, порядок блоков соответствует принятому концепту.

### SC-005 — якоря и клавиатура

**Covers:** R-006. **Уровень:** component.

**Given** посетитель выбирает якорь или перемещается клавиатурой. **When** активирует действие. **Then** каждый якорь имеет соответствующий раздел, а копирование/ссылки имеют понятное имя и видимый фокус.

### SC-006 — только IBAN

**Covers:** R-007. **Уровень:** unit + component.

**Given** на странице показан IBAN, в том числе с визуальным переносом. **When** посетитель выбирает его копирование. **Then** буфер получает только исходную последовательность IBAN без добавленных пробелов, подписей и переводов строки.

### SC-007 — полный набор

**Covers:** R-008. **Уровень:** unit + component.

**Given** посетитель читает выбранную языковую версию. **When** копирует все реквизиты. **Then** получает ровно шесть согласованных полей в порядке: наименование, код, выписка, IBAN, банк, МФО; подписи соответствуют языку, значения — единому источнику.

### SC-008 — ожидание копирования

**Covers:** R-009. **Уровень:** component.

**Given** системная операция ещё не закончилась. **When** посетитель повторно активирует ту же кнопку. **Then** новая операция не запускается, действие временно недоступно и его занятость доступна вспомогательным технологиям.

### SC-009 — успешное копирование

**Covers:** R-009. **Уровень:** component.

**Given** системная операция завершилась успешно. **When** посетитель остаётся на странице. **Then** рядом с соответствующим действием появляется «Скопійовано / Скопировано», а результат доступен вспомогательным технологиям без перемещения фокуса.

### SC-010 — отказ, недоступность и повтор

**Covers:** R-009. **Уровень:** component.

**Given** доступ к буферу отклонён либо функция недоступна. **When** посетитель пытается скопировать данные. **Then** видит инструкцию ручного копирования, значения остаются выделяемыми, звонок/переход не запускается. **When** повторяет действие после устранения причины. **Then** операция снова доступна и может завершиться успешно.

### SC-011 — контекст оплаты и менеджер

**Covers:** R-010. **Уровень:** component + server integration.

**Given** посетителю нужны условия оплаты заказа. **When** читает пояснение и активирует телефон. **Then** видит предложение согласовать наличие, сумму и реквизиты, а телефонное действие использует актуальный номер сайта независимо от копирования.

### SC-012 — связанные материалы

**Covers:** R-011. **Уровень:** component для назначений; source/integration подтверждение destinations через EN-002.

**Given** связанные материалы опубликованы и проверены. **When** посетитель выбирает доставку/оплату, оферту либо политику. **Then** обычная ссылка ведёт на соответствующий материал в текущем языке. Наличие только ссылки в меню не считается готовностью целевой страницы.

### SC-013 — metadata и индексация

**Covers:** R-012. **Уровень:** SEO unit; реальный head отдельно.

**Given** запрошена любая из двух языковых страниц в выбранном окружении. **When** формируются её публичные сведения для поисковика. **Then** title/description локализованы, canonical относится к этой странице и языку, UK/RU взаимно перечислены, x-default указывает на UK; индексация разрешена только при существующих production-настройках сайта.

### SC-014 — хлебные крошки

**Covers:** R-013, R-004. **Уровень:** SEO unit + server integration.

**Given** посетитель читает видимые крошки «Главная → Реквизиты». **When** поисковик читает структурированные сведения. **Then** получает те же две позиции, подписи текущего языка и абсолютные канонические URL; новые банковские сущности и повторная организация не добавляются.

### SC-015 — sitemap и сохранение соседних страниц

**Covers:** R-014, R-001. **Уровень:** sitemap integration.

**Given** сформирован общий sitemap сайта. **When** выбираются записи реквизитов. **Then** присутствует ровно один адрес на каждый язык с текущими языковыми альтернативами, без вымышленной даты; остальные информационные адреса сохранены.

### SC-016 — неподдерживаемый язык

**Covers:** R-015. **Уровень:** source/type integration существующего locale guard; реальный HTTP отдельно.

**Given** запрошен неподдерживаемый языковой адрес реквизитов. **When** сайт разрешает маршрут. **Then** используется существующее поведение отсутствующей страницы, без обычного ответа реквизитов и без молчаливого fallback на UK.
