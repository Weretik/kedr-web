# Концепт страницы «Реквизиты»

Статус: визуальный концепт для обсуждения, 2026-11-03. Это не готовая к реализации SDD и не изменение production-кода.
Проект: Kedr, новый публичный Next.js сайт, `apps/site`.

[Макет: desktop/mobile, UK/RU, light/dark](requisites-concept.png).
[Точный промпт генерации](requisites-prompt.txt). Растровый макет создан встроенным imagegen по пользовательскому скриншоту страницы возвратов.

## Задача посетителя

Найти сведения об администрации ClassKedr, скопировать IBAN либо все реквизиты и связаться с менеджером для согласования оплаты конкретного заказа.

Реквизиты администрации не следует автоматически представлять как универсальные реквизиты продавца любого заказа. Это следует из старого источника и его публичной оферты.

## Композиция

1. Существующий shell: верхняя навигация, каталог, поиск, контактные действия, категории; на телефоне компактная шапка и отдельная строка поиска.
2. Хлебные крошки, H1 «Реквізити / Реквизиты», короткий вводный текст и якоря к администрации, банку и оплате.
3. Две равные панели: слева администрация, наименование, код и выписка; справа IBAN, банк, МФО и основное действие «Скопіювати всі реквізити / Скопировать все реквизиты».
4. Тихая полоса «Перед оплатою замовлення / Перед оплатой заказа»: согласовать наличие, окончательную сумму и реквизиты с менеджером; ссылка на доставку и оплату.
5. Юридические ссылки и компактный контактный блок с телефоном и действием звонка.
6. Существующий footer с пунктом реквизитов в информации о компании.

На desktop панели стоят в две колонки. На mobile: администрация → банк и копирование → пояснение об оплате → юридические ссылки → контакт → footer. IBAN получает собственную строку с отдельной кнопкой копирования и не расширяет страницу.

## Визуальные правила

- Сохраняется действующая [дизайн-система сайта](../../../../../standards/site/design-system.md) и паттерн [информационных страниц](../../../../../features/site/returns-exchanges.md).
- Onest для интерфейса; JetBrains Mono только для IBAN, номера и кодов. H1 около 30/36 px, текст 14–16 px.
- Контент до 1440 px; отступы по краям 16 px, с lg — 24 px. Панели с тонкой границей, радиусами 10–16 px и без декоративных теней.
- Цвета берутся из [global.css](../../../../../../apps/site/src/app/global.css), а не измеряются по старому скриншоту.
- Светлая тема: фон #FFFFFF, текст #0F110F, границы #E3E6DF, зелёный текст #2A7323.
- Тёмная тема: фон #0C0D0C, панели #111311, текст #EDEFEA, границы #242823, зелёный текст #7DD06F.
- Brand fill/icon #3FA435. Основные кнопки — ink в light и светлые с тёмным текстом в dark. Цвет кнопок в тёмной теме сознательно следует актуальным токенам, которые отличаются от референса.
- Иконки Lucide, stroke 1.75; зоны нажатия копирования не меньше 44 px.
- Макет — визуальный ориентир. Точные значения данных, тексты, размеры, токены и состояния задаются этим описанием и кодом проекта; растровое изображение не служит источником реквизитов.

## Взаимодействия для будущей реализации

- Якоря прокручивают к соответствующему разделу. Сохраняются видимый focus и учёт sticky-шапки.
- Кнопка возле IBAN копирует только исходное значение `UA303052990000026007025905216`, без пробелов и переносов, добавленных для визуальной верстки.
- Основное действие копирует наименование, код, выписку, IBAN, банк и МФО с понятными подписями. Содержимое согласуется вместе с актуальными реквизитами.
- Пока системная операция копирования выполняется, повторная отправка недоступна.
- Успех: иконка Check и «Скопійовано / Скопировано», сообщение через `aria-live="polite"`.
- Ошибка или недоступный clipboard: данные остаются выделяемыми, рядом появляется инструкция скопировать вручную и возможность повторить. Ошибка не запускает звонок.
- Телефон — действие `tel:+380687135049`; locale/theme сохраняют паттерн shell. На странице нет ввода персональных данных.
- Переиспользуется подход [копирования телефона страницы контактов](../../../../../features/site/contacts.md); отдельный общий clipboard-примитив пока не проектируется.

## Граница результата и проверки

Подготовлены только PNG-концепт, его промпт и это описание. Маршруты, данные, SEO, sitemap, компоненты и production CSS не изменяются на этапе концепта.
Реализация и её SDD следуют после обратной связи по композиции. Существующие публичные URL потребуется сохранить по правилам миграции.

Проверка текущего результата: сравнение источников данных, правил темы и статического макета четырёх вариантов; независимая проверка концепта агентом. Это не проверка геометрии работающего приложения.
Браузер, запуск приложения, build, manual/E2E и тесты для production-кода не выполнялись.
