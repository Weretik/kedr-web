# Клієнти — React та візуальна взаємодія

Візуальна основа: передані референси Devias Kit Pro списку й картки клієнта. Застосувати їхні композицію меню, заголовка, округлої Card, компактної таблиці та інформаційних блоків у наявній Admin theme. Tabs Active/Pending/Blocked, аватари, quota, payments, billing, shipping і notifications з референсу не переносити: таких даних і фільтрів немає в Kedr API.

- Список: заголовок «Клієнти», MUI Data Grid із колонками «Клієнт», «Телефон», «ID», «Дії» та одним постійно відкритим `QuickFilterControl` у toolbar таблиці. Поле «Пошук клієнтів» має іконку лупи ліворуч усередині поля; окремої форми та кнопки «Знайти» немає. `filterModel.quickFilterValues` керується feature і надсилає `searchTerm` до API; `paginationMode="server"`, `rowCount` відповідає `totalRecords` після пошуку. Сортування й фільтри колонок вимкнені. «Дії» — іконка ока з підказкою «Переглянути клієнта» та доступним ім'ям. Усі колонки доступні через горизонтальне прокручування на вузькому екрані. Вбудовані підписи й керування локалізовано українською через Admin theme.
- Пошук і сторінку тримати у feature та URL; debounce текстового вводу, page reset до 1, відновлення пошуку після повернення з деталей. Не показувати окремої форми пошуку чи підпису з кількістю й описом серверної роботи під таблицею.
- Деталі: зберегти MUI Link зі стрілкою «Назад до клієнтів» і заголовок «Деталі клієнта». Нижче розмістити три окремі компактні MUI Card: основна інформація (ім'я один раз та ID), контакти (телефон і Email), типи цін (за замовчуванням і за категоріями). Використати підписані пари значень без таблиць, щільні відступи й кольори чинної Admin theme. На телефоні — один стовпець, на планшеті — два, на широкому екрані — три. Числові ID типів цін замінити на підтверджені backend назви, а категорію показати як назву з ID; `null` назви відобразити як «Назва недоступна», не як ID типу цін. Для `phone=null` показати «Не вказано».
- Loading/empty/error/not found мають стабільні розміри й короткі українські повідомлення. Перевірити фокус, accessible names, keyboard, ширину 320 px і desktop.

Перевірки: лише автоматичні focused/component tests зміненої фічі для станів і навігації. Підключення тем, локалі й breakpoints звіряти за кодом. Browser journey список → картка → назад можливий тільки після окремого запитання й прямого дозволу користувача на конкретну перевірку.
