**Current contract as of 2026-10-19:** `page>=1`, `pageSize` 1..100, defaults 1/20; server ordering by name then ID. The synchronized snapshot includes server-side `searchTerm`, filters, and `sort`. The list returns `pagedInfo` and rows with `counterpartyId`, `name`, and nullable `phone`. Detail returns these fields, `email`, `defaultPriceTypeId`, nullable `defaultPriceTypeName`, and `categoryPriceTypes[{categoryId,categoryName,priceTypeId,priceTypeName}]`.

**Provider capabilities:** `GET /api/admin/customers` accepts `searchTerm`, exact filters `counterpartyId`, `name`, `phone`, `sort`, `page`, and `pageSize`. `searchTerm` searches ID, name, and phone; additional API filters are combined with AND. Allowed `sort` values are `name`, `-name`, `counterpartyId`, `-counterpartyId`, `phone`, and `-phone`; the secondary ID ordering is deterministic. All conditions and sorting run on the server before `Skip/Take`; `pagedInfo.totalRecords` counts filtered records. Text conditions have `maxLength=100`; the server applies `Trim` and a case-insensitive substring match. Phone is compared with the stored string without digit normalization. A condition empty after `Trim` means no filter. The current Admin UI sends `searchTerm`, `sort`, `page`, and `pageSize`.

**Separate detail increment, 2026-10-19:** backend OpenAPI `getAdminCustomerById` now defines `defaultPriceTypeName: string | null` and `categoryPriceTypes[{categoryId,categoryName,priceTypeId,priceTypeName}]`, where both names are nullable; existing IDs remain for identity. The backend gets names from Catalog `PriceType.PriceTypeName` and `ProductCategory.Name`. The UI shows the price-type name instead of its ID and each category by name with its ID; `null` is displayed as “Name unavailable”. Frontend snapshot/generated types are synchronized with backend commit `8fc8729`.

At the data-access boundary, use `operations[...]`, runtime validation, and a mapper; the UI sees only the model. RTK Query cache keys include request parameters and the detail ID. Changing search or sort in the Admin UI resets page to 1; additional filters remain available in the API contract without controls on this screen. Validate a non-empty ID before the request; `404` means not found, and transport errors offer safe retry. Do not add addresses, statuses, or other DTO fields.

OpenAPI has `security: []`; the backend controller is temporarily `[AllowAnonymous]`. Production exposure requires a backend access decision. Synchronize contract changes using the [workflow](../../../../../contracts/README.md), without manually editing the frontend snapshot/generated files. Verify only the changed contract and this feature's tests; a full run or browser check requires a separate direct user request.
