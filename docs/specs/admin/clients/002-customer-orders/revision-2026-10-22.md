# Change 2026-10-22 — Orders table in customer details

**Status:** SDD, not implemented. This document supplements the [existing SDD](README.md); the original R-001–R-004, SC-001–SC-004, and evidence remain as history. The new rules replace conflicting parts of R-001–R-002 only for the orders table on the customer details page. The main orders page is described in the [orders SDD](../../orders/001-order-workspace/revision-2026-10-22.md).

## Rules and scenarios

- **R-005.** In the «Замовлення» tab of customer details, do not show the «Клієнт» column or search field. Continue applying the fixed `counterpartyId` from the customer route on the server for every request; data for another customer must not appear.
- **R-006.** Add an MUI date range picker for order creation dates in the `Europe/Kyiv` time zone. The range is independent of the main list state and the drafts tab, is stored in the customer panel URL, resets pagination to the first page, and affects `totalRecords`. Empty/invalid bounds have distinct accessible states.
- **R-007.** Preserve the current view actions, return-to-tab behavior, loading/empty/error states, and accessibility. Use MUI/MUI X components without a custom date picker.

| ID         | Given / When / Then                                                                                                                                                                                                                          |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **SC-005** | Given a customer has orders on different dates; When the manager opens the customer details and sets a range; Then only that customer's orders within the range are shown, with the correct count and without the customer column or search. |
| **SC-006** | Given the manager navigates from a filtered table to order details; When they return; Then the same customer, tab, and date range are shown.                                                                                                 |

## Design and plan

The shared `OrderTables` currently receives `counterpartyId` from `CustomerOrdersPanel` but still shows search and the customer column. Add an explicit customer-panel context for the toolbar/columns; do not make a separate copy of the table. `getAdminWorkspaceOrders` remains the only operation: fixed `counterpartyId` + new `createdFrom`/`createdTo` + pagination. The Sales workspace SDD defines the backend contract and timezone boundary; the frontend synchronizes the snapshot through the standard workflow.
