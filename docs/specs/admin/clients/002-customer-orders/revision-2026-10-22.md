# Зміна 2026-10-22 — таблиця замовлень у деталях клієнта

**Статус:** SDD, не реалізовано. Цей документ доповнює [наявну SDD](README.md); початкові R-001–R-004, SC-001–SC-004 і докази зберігаються як історія. Нові правила замінюють суперечливі частини R-001–R-002 тільки для таблиці замовлень на сторінці деталей клієнта. Головна сторінка замовлень описана в [SDD orders](../../orders/001-order-workspace/revision-2026-10-22.md).

## Правила й сценарії

- **R-005.** У вкладці «Замовлення» деталей клієнта не показувати стовпець «Клієнт» і поле пошуку. Фіксований `counterpartyId` із маршруту клієнта й далі застосовувати на сервері до кожного запиту; дані іншого клієнта не з’являються.
- **R-006.** Додати MUI-вибір діапазону дат створення замовлення в часовій зоні `Europe/Kyiv`. Діапазон незалежний від стану головного списку й від вкладки чернеток, зберігається в URL панелі клієнта, скидає pagination на першу сторінку та впливає на `totalRecords`. Порожні/невалідні межі мають окремі доступні стани.
- **R-007.** Чинні дії перегляду, повернення до вкладки, стани loading/empty/error і доступність зберігаються. Використовувати MUI/MUI X компоненти без власного date picker.

| ID         | Given / When / Then                                                                                                                                                                                    |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SC-005** | Given клієнт має замовлення в різні дати; When менеджер відкриває його деталі й задає діапазон; Then бачить лише замовлення цього клієнта в межах дат, правильний count, без стовпця клієнта й пошуку. |
| **SC-006** | Given менеджер перейшов із відфільтрованої таблиці в деталі замовлення; When повертається; Then бачить того самого клієнта, вкладку та діапазон дат.                                                   |

## Дизайн і план

Спільний `OrderTables` зараз отримує `counterpartyId` із `CustomerOrdersPanel`, але все одно показує пошук і стовпець клієнта. Ввести явний контекст панелі клієнта для toolbar/columns; не робити окрему копію таблиці. `getAdminWorkspaceOrders` лишається єдиною операцією: fixed `counterpartyId` + нові `createdFrom`/`createdTo` + пагінація. Backend-контракт і timezone boundary визначає SDD Sales workspace; frontend синхронізує snapshot за штатним workflow.
