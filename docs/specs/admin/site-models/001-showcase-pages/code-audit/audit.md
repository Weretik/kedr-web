# Feature audit: Admin site models «Моделі», «Перевірка», «Ознаки та фільтри»

- **Scope:** `libs/admin/site-models/{model,data-access,ui,feature}`, `libs/admin/catalog-attributes/feature` (codes count), `libs/admin/products/feature` (site model slot), `libs/admin/core/shell/src/navigation/navigation-groups.tsx`, `libs/admin/dashboard/model/src/mappers/catalog-attention.ts`, `apps/admin/src/app/router/app-router.tsx`, `apps/stack-e2e/src/admin/site-model.spec.ts`.
- **Date:** 2026-11-26, after implementation (TS-005), by skill `frontend-code-audit`.
- **Sources:** [code organization](../../../../../standards/shared/code-organization.md), [list and detail pages](../../../../../standards/admin/list-detail-pages.md), [idempotency rules](../../../../../standards/shared/idempotency-rules.md), [contracts](../../../../../contracts/README.md), KedrStore `docs/sdd/architecture/overview/quality-targets.md`, feature review list of the architecture toolkit.
- **Method:** static review of every changed file, `npm run architecture:structure`, `npm run architecture:boundaries`, `npm run docs:check`, `npm run contracts:check`, lint, typecheck and focused tests of every changed project. No browser or E2E run (not permitted without the owner's separate consent).

## Step 0: quality targets

The client depends on the API read P95 ≤ 1 s and write P95 ≤ 2 s from the backend quality targets. «Моделі» makes one paged `GET` plus the category tree; the model page one `GET`; a panel save one `PUT`/`POST`. The backend answers lists from its cached site models snapshot. The project still has no target for Admin screen load time (AF-001).
