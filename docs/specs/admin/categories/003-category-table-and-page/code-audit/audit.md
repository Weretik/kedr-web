# Feature audit: Admin categories table and page

- **Scope:** `libs/admin/categories/{model,data-access,ui,feature}`, `libs/admin/shared/ui/src/lib/slug/`, `apps/stack-e2e/src/admin/category-texts.spec.ts`, the contract copy, `docs/features/admin/categories.md`, `docs/standards/admin/list-detail-pages.md`.
- **Date:** 2026-11-26, after implementation, by skill `frontend-code-audit`.
- **Sources:** [code organization](../../../../../standards/shared/code-organization.md), [list and detail pages](../../../../../standards/admin/list-detail-pages.md), [idempotency rules](../../../../../standards/shared/idempotency-rules.md), [contracts](../../../../../contracts/README.md), KedrStore `docs/sdd/architecture/overview/quality-targets.md`, feature review list of the architecture toolkit.
- **Method:** static review of every changed file, `npm run architecture:structure`, `npm run architecture:boundaries`, `npm run docs:check`, lint and typecheck of the five changed projects and the admin app, focused tests. No browser or E2E run (not permitted without the owner's separate consent).

## Step 0: quality targets

The client depends on the API read P95 ≤ 1 s and write P95 ≤ 2 s from the backend quality targets. The list makes one `GET /api/categories` (the whole tree, as before); the page adds the by-id read and the content read; every save is one `PUT`/`POST`. The project still has no target for Admin screen load time (AF-001).
