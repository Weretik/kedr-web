# Зміна 2026-10-22 — кошик, списки та оформлення Admin

**Статус:** реалізацію TS-007 і frontend-частини TS-008 звірено з кодом; backend date contract і provider snapshot ще не синхронізовані. Цей інкремент доповнює [початкову специфікацію](README.md); історичні R-001–R-010, SC-001–SC-008 і докази виконання залишаються записом попереднього стану. Вимоги нижче замінюють суперечливі частини R-001, R-002, R-005 і R-007 лише для нового інкременту.

## Мета й межі

Менеджер бачить кількість позицій поточного набору в шапці, швидко переходить до оформлення, працює зі списками за пошуком і датою, бачить зрозумілі назви та попередню вартість до підтвердження. Чернетка й оформлення відкриваються окремими діалогами. Зміни стосуються Admin React; Mobile і Storefront поза обсягом. Кількість у шапці — число **різних позицій**, а не сума одиниць товару.

## Правила продукту

- **R-011.** Шапка Admin показує MUI-іконку кошика з badge кількості позицій поточного локального набору. Натискання веде на `/orders/new`; число оновлюється після додавання, зміни й видалення позиції та після успішного оформлення/збереження.
- **R-012.** На головній сторінці замовлень обидві вкладки не показують вибір клієнта. Пошук лишається серверним: замовлення — номер/клієнт, чернетки — назва/клієнт. Поле має таку саму MUI X-композицію з іконкою пошуку, що й список товарів; текст підказки зникає після вводу й не стає floating label.
- **R-013.** На головній сторінці обидві вкладки мають незалежний діапазон дат у URL. Замовлення фільтруються за датою створення, чернетки — за датою створення. Початок і кінець включно для календарних дат у часовій зоні `Europe/Kyiv`; порожня межа не обмежує вибірку. Невалідний або обернений діапазон не надсилається. Зміна діапазону скидає сторінку на першу; `totalRecords` обчислює сервер після фільтрації й до пагінації.
- **R-014.** У виборі клієнта показується лише назва, без ID; вибір ідентифікується незмінним `counterpartyId`. Користувач може знайти й обрати будь-якого клієнта, а не лише перші 20. Список завантажується посторінково з підвантаженням при прокручуванні; вже вибраний клієнт лишається видимим поза поточною сторінкою.
- **R-015.** Кожний товар у наборі показує назву, кількість із кнопками «+»/«−», ціну одиниці, суму рядка та загальну суму. Після вибору клієнта й отримання серверних цін зміна кількості одразу оновлює видимий попередній підсумок із завантажених цін; новий server quote запитується паралельно. Якщо ціна ще не завантажена, недоступна або ціноутворення залежить від зміненої кількості, UI не видає попередню суму за підтверджену. Назва товару має бути доступна навіть до першого quote через наявні дані каталогу або цільове читання; ID не є її заміною.
- **R-016.** Під списком товарів залишаються три MUI-кнопки: «Додати з каталогу» відкриває каталог; «Зберегти як чернетку» відкриває діалог із обов’язковою назвою та необов’язковою нотаткою, діями «Зберегти»/«Скасувати»; «Оформити замовлення» відкриває діалог із необов’язковим коментарем, поточною підтвердженою сумою та діями «Відправити»/«Скасувати». Постійно видимі форми з-під списку прибираються. Невдала операція не очищує набір.
- **R-017.** Ціна й сума в браузері є попереднім відображенням, а сервер лишається власником остаточного розрахунку на `quoteAdminWorkspaceOrder` і `createAdminWorkspaceOrder`. Відправлення недоступне до актуального quote для поточного клієнта й складу; `409 quote_changed` показує нову суму й вимагає повторного підтвердження в тому самому сценарії.
- **R-018.** На всіх зачеплених екранах використовуються MUI/MUI X компоненти, тема, українські підписи й доступні назви іконок. Не створювати власні аналоги наявних MUI Badge, IconButton, Dialog, TextField, Autocomplete, DataGrid і DatePicker.

## Перевірений базис і дизайн

- `AdminTopBar` нині не показує набір. `current-order-set.ts` зберігає тільки `productId/quantity` у browser storage; ціни й дані клієнта туди не записувати. App router уже має `/orders/new` і callback додавання з Products.
- `OrderTables` спільний для головної сторінки й деталей клієнта. Нові параметри дат мають бути окремими для вкладок і не змішуватися з фіксованим `counterpartyId` панелі клієнта. Відмінності панелі клієнта визначає [її SDD](../../clients/002-customer-orders/README.md).
- `CustomerPicker` зараз читає лише page 1/size 20 і показує ID у назві. Використати чинний `getAdminCustomers` із server search/pagination та `getAdminCustomerById` для поточного вибору; окремий endpoint повного списку не планується.
- `OrderLineEditor` уже показує server quote, але назви без quote замінює `ID`, а зміну кількості має тільки через числове поле. Дані каталогу можуть дати назву; клієнтоспецифічні ціни беруться з quote. Попередній локальний перерахунок не змінює API DTO й не зберігає ціну в browser storage.
- Пошук реалізовано через MUI X `QuickFilter`/`QuickFilterControl` за патерном таблиці товарів без імпорту products feature в orders. Діапазон дат використовує MUI X `DatePicker`, `LocalizationProvider`, `AdapterDayjs`; у lockfile зафіксовано `@mui/x-date-pickers` 9.10.1 та `dayjs` 1.11.13.
- Архітектурні межі: `apps/admin` володіє композицією shell/customer adapter; `orders/feature` — URL, діалогами й станом; `orders/ui` — MUI-відображення; `orders/data-access` — generated transport/runtime mapping. Не переносити HTTP у UI.

## API і залежності

| Порядок | Операція                                                                         | Рішення                                                                                                                                 |
| ------- | -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 1       | `getAdminWorkspaceOrders`                                                        | backend додає діапазон `createdFrom`/`createdTo` до server pagination; frontend синхронізує snapshot після версійного backend контракту |
| 1       | `getAdminOrderDrafts`                                                            | backend додає `createdFrom`/`createdTo` за `CreatedAtUtc`                                                                               |
| 2       | `getAdminCustomers`, `getAdminCustomerById`                                      | чинний контракт достатній для всіх сторінок клієнтів і відновлення вибору                                                               |
| 2       | `quoteAdminWorkspaceOrder`, `createAdminWorkspaceOrder`, `createAdminOrderDraft` | форми й попередній розрахунок не змінюють DTO; фінальна ціна лишається серверною                                                        |

**Обмеження контракту дат:** UI передає `createdFrom` і `createdTo` через `orders.api.ts`, але поточний provider snapshot `docs/contracts/openapi/sales/admin-order-workspace.openapi.yaml` не оголошує ці query-параметри для `getAdminWorkspaceOrders` і `getAdminOrderDrafts`; generated types також не підтверджують їх. Тому frontend date controls, URL і формування запиту реалізовані, але сумісність із backend та включні межі `Europe/Kyiv` не підтверджені цим snapshot. Після зміни provider OpenAPI синхронізувати snapshot і generated types за [workflow](../../../../contracts/README.md); generated artifacts вручну не редагувати.

## Стан реалізації (2026-10-22)

- **TS-007 / R-011:** `AdminShellRoute` передає `lines.length` у `AdminLayout`, а `AdminTopBar` показує MUI Badge та переходить на `/orders/new`. `admin-top-bar.spec.tsx` пройшов: число позицій і перехід перевірено.
- **TS-008 / R-012–R-013:** frontend код реалізує окремі URL ключі дат для вкладок, перевіряє календарні значення й порядок діапазону, пропускає запит для невалідного діапазону та скидає сторінку на першу після зміни дат. `OrderGridToolbar` використовує MUI X `QuickFilter` і `DatePicker`. `order-tables.spec.tsx` покриває URL і передавання query параметрів; відповідність backend date contract і `Europe/Kyiv` лишається непідтвердженою до синхронізації snapshot.
- **TS-009:** посторінковий MUI `CustomerPicker` показує назви без ID; його два компонентні тести пройшли.
- **TS-010:** `OrderLineEditor` показує назви, кнопки кількості й попередню суму, а актуальний серверний quote має пріоритет. Два вузькі тести пройшли.
- **TS-011:** три кнопки й два MUI Dialog реалізовані; `new-order-page.spec.tsx` пройшов для чернетки та повторного підтвердження після 409. Окремий сценарій cancel/send ще не автоматизовано.

**Готовність:** frontend код TS-007–TS-011 реалізовано. `tsc` для Admin і вузькі Vitest перевірки пройшли. Backend date contract уже змінено у KedrStore, але frontend machine-managed snapshot/generated types ще не синхронізовано: `contracts:sync` вимагає чистий backend checkout із commit provenance. Ручну браузерну перевірку не проводили.
