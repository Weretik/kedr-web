# Товари — API-контракт

**Provider:** KedrStore `docs/sdd/contracts/openapi.yaml`; frontend snapshot [SOURCE](../../../../../contracts/openapi/SOURCE.md) за backend commit `8fc87294df4ce6bdb871107cb276e7cb6c89e5e8`. **Стан:** списки із серверними фільтрами й окремий Admin endpoint деталей реалізовано та синхронізовано 2026-10-19. Frontend YAML/generated файл не редагувати вручну.

| operationId                             | Метод і шлях                                    | Сценарії               | Споживач                                       |
| --------------------------------------- | ----------------------------------------------- | ---------------------- | ---------------------------------------------- |
| `getAdminProducts`                      | `GET /api/admin/products`                       | SC-001, SC-003         | наявний `@admin/products/data-access`          |
| `getAdminProductsWithUnavailablePhotos` | `GET /api/admin/products/missing-photos`        | SC-002, SC-005, SC-006 | новий endpoint у `@admin/products/data-access` |
| `getAdminProductBySlug`                 | `GET /api/admin/products/by-slug/{productSlug}` | SC-004, SC-005, SC-010 | `@admin/products/data-access` |

**Чинний контракт:** звичайний [consumer contract](../../../../../contracts/catalog/admin-products.md) має `searchTerm`, `categorySlug`, `categoryId`, `inStock`, `isSale`, `isNew`, `exportToSite`, `priceFrom`, `priceTo`, `sort`, `page`, `pageSize`. Режим [«Без фото»](../../../../../contracts/catalog/missing-photo-products.md) має `searchTerm`, чотири булеві ознаки, `sort`, `page`, `pageSize`. Admin використовує окрему операцію деталей; публічні [деталі](../../../../../contracts/catalog/public-products.md) лишаються для Storefront і Mobile.

**Цільовий provider-контракт:** `GET /api/admin/products` додає `exportToSite?: boolean`; `inStock`, `isSale`, `isNew`, `exportToSite` мають розрізняти відсутній параметр / `true` / `false` і реально застосовувати обидва boolean значення. `GET /api/admin/products/missing-photos` додає `searchTerm`, ті самі чотири ознаки й `sort`. Для обох списків `sort=IdAsc|IdDesc|NameAsc|NameDesc|PriceAsc|PriceDesc`; category і price range діють лише у звичайному списку, якщо provider не розширить контракт окремо. Умови застосовуються до всієї вибірки до сортування та `page` (1-based), `pageSize` 1..100; `pagedInfo.totalRecords` — кількість після фільтрації. За рівних ключів сортування потрібен стабільний порядок за ID. Фільтри Data Grid із непідтримуваними операторами не надсилати й не створювати ілюзію серверної фільтрації.

**Цільові деталі:** `GET /api/admin/products/by-slug/{productSlug}` (`operationId: getAdminProductBySlug`) повертає `id`, `nameUk`, `nameRu`, `productSlug`, `photo`, `scheme`, `categoryId`, `categoryName`, `inStock`, `isSale`, `isNew`, `exportToSite`, `price`, `stock`, `quantityInPack`. Чинний Admin URL `/catalog/:productSlug` зберігається, тому прямі посилання працюють без міграції; slug із URL валідовується перед запитом. Публічне посилання будувати із `productSlug` лише за `exportToSite=true`; це посилання на storefront, а не HTTP-запит за деталями Admin. Наявність зображення перевіряє компонент під час завантаження, а не список.

Generated `operations[...]` використовувати тільки в data-access, перевіряти unknown response в runtime, повертати UI модель. RTK Query має окремий cache key на режим + усі умови + sort/page/size і slug деталей; `404` відображати як недоступні деталі, інші помилки — retry. Після backend-зміни синхронізувати snapshot/generated за [workflow](../../../../../contracts/README.md) і перевірити лише змінений контракт та тести фічі. Browser/E2E/повний прогін — тільки за окремим прямим запитом користувача. API Admin тимчасово anonymous, тому production exposure залежить від backend access policy.
