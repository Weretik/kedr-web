# Products — API contract

**Provider:** KedrStore `docs/sdd/contracts/openapi.yaml`; frontend snapshot [SOURCE](../../../../../contracts/openapi/SOURCE.md) at backend commit `8fc87294df4ce6bdb871107cb276e7cb6c89e5e8`. **Status:** lists with server-side filters and a separate Admin detail endpoint were implemented and synchronized on 2026-10-19. Do not edit frontend YAML/generated files manually.

**Current contract:** the regular [consumer contract](../../../../../contracts/catalog/admin-products.md) has `searchTerm`, `categorySlug`, `categoryId`, `inStock`, `isSale`, `isNew`, `exportToSite`, `priceFrom`, `priceTo`, `sort`, `page`, and `pageSize`. The [“No photo”](../../../../../contracts/catalog/missing-photo-products.md) mode has `searchTerm`, four boolean flags, `sort`, `page`, and `pageSize`. Admin uses a separate detail operation; public [details](../../../../../contracts/catalog/public-products.md) remain for Storefront and Mobile.

**Target provider contract:** `GET /api/admin/products` adds `exportToSite?: boolean`; `inStock`, `isSale`, `isNew`, and `exportToSite` must distinguish omitted / `true` / `false` and actually apply both boolean values. `GET /api/admin/products/missing-photos` adds `searchTerm`, the same four flags, and `sort`. For both lists, `sort=IdAsc|IdDesc|NameAsc|NameDesc|PriceAsc|PriceDesc`; category and price range apply only to the regular list unless the provider expands the contract separately. Conditions apply across the full result set before sorting and `page` (1-based), `pageSize` 1..100; `pagedInfo.totalRecords` is the post-filter count. Ties require stable ordering by ID. Do not send Data Grid filters with unsupported operators or imply server-side filtering that does not exist.

**Target detail:** `GET /api/admin/products/by-slug/{productSlug}` (`operationId: getAdminProductBySlug`) returns `id`, `nameUk`, `nameRu`, `productSlug`, `photo`, `scheme`, `categoryId`, `categoryName`, `inStock`, `isSale`, `isNew`, `exportToSite`, `price`, `stock`, and `quantityInPack`. The current Admin URL `/catalog/:productSlug` is retained, so direct links work without migration; the slug from the URL is validated before the request. Build a public link from `productSlug` only when `exportToSite=true`; this is a storefront link, not an HTTP request for Admin details. The component checks image availability while loading, not the list.

Use generated `operations[...]` only in data-access, validate unknown responses at runtime, and return a UI model. RTK Query uses a separate cache key for mode + all conditions + sort/page/size and the detail slug; display `404` as unavailable details and offer retry for other errors. After a backend change, synchronize snapshot/generated files using the [workflow](../../../../../contracts/README.md) and verify only the changed contract and feature tests. Browser/E2E/full runs require a separate direct user request. Admin API is temporarily anonymous, so production exposure depends on the backend access policy.
