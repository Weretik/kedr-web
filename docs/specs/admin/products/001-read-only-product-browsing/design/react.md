# Products — React and visual interaction

Visual basis: the provided Devias Kit Pro references for the product list and detail page. They guide visual style, not fields or actions. Keep the existing Admin theme: heading above a rounded MUI Card, compact top tabs, a restrained grid with photo, scheme, and basic data, and pagination. Do not carry over the reference's edit form or Save/Delete buttons.

The [Admin list/detail standard](../../../../../standards/admin/list-detail-pages.md) defines the composition shared with the customer card; this document defines product fields, sections, and contracts.

- Above the table inside the Card: three accessible tabs, «Усі товари», «Без фото», and «На сайті», inset from the edge as in the reference. Below them, a Data Grid with search, built-in filters, and server-side pagination. Use only `pagedInfo.totalRecords` from the active mode for the count; do not duplicate it in text below the table.
- Do not restore the old separate search/filter panel. Use controlled `filterModel`, `sortModel`, `paginationModel`, `filterMode="server"`, `sortingMode="server"`, and `paginationMode="server"`; integrate search with Data Grid and debounce text input. The mapper supports only operators/values available in the API. When conditions or sort change, set page=1 and persist state in the URL; the API receives pageIndex+1. In «Без фото», do not show category/price-range filters absent from its contract. `rowCount` is the server count after filtering.
- Apply Ukrainian locales for MUI Material and MUI X Data Grid at the Admin theme level for all tables, including pagination and accessible button names.
- The non-sortable, non-filterable «Дії» column contains an eye icon with a tooltip and accessible name. Availability, sale, new, and «На сайті» are separate columns with a checkmark only for true; false cells have no checkmark and retain a clear accessible name. Three independent MUI Select controls (“All/Yes/No”) appear in the availability, sale, and new column headers; their URL values combine in the server request and reset to the first page when changed. «На сайті» has no column filter: its separate tab sends `exportToSite=true`. Product photos are 56 × 56 px in 72 px rows.
- The Devias Kit Pro reference guides a restrained composition and return navigation as an arrow text link above the heading; do not carry over the edit form or Save/Delete. The read-only card shows the product name exactly once in the information section, Ukrainian and Russian names, only true flags as four colored MUI Chips without «Так»/«Ні» words, and a compact “field — value” table in that same section. Remove category slug. On wide screens, the three separate sections appear in this order: **product photo → basic information → product scheme**, when the scheme loads. On phones and tablets, sections shift to one/two columns according to theme breakpoints and retain this order. Each available image is directly clickable and opens in an MUI Dialog with an accessible name, keyboard dismissal, and focus return. In the main section, show a prominent «Відкрити на сайті» button only when `exportToSite` and slug are present, and a «Сховище фото» button for every product. Keep the storefront domain in configuration and URI-encode the slug; the photo folder is `https://images-kedr.cdn.express/~/o/products`. Do not show a separate JPG button below the image. The verified backend importer normalizes ID to a number and builds `https://images-kedr.cdn.express/products/{id}.jpg`; Admin API returns the stored `photo`. Do not render a failed scheme or empty placeholder. `feature` owns the route, query, and loading states; cards, table, images, and Dialog are presentational `ui` components that receive data through props.
- Shared `AdminLayout` does not show breadcrumbs on any page. Return navigation from product details remains a feature-local arrow link that preserves list query parameters.
- Loading, empty, error, and not-found states do not cause layout shifts. On narrow viewports, the table scrolls within the Card. Check keyboard use and focus after navigating to details and back.

Technical checks: only automated component/integration tests for the changed feature's tabs, states, action, and route. Verify theme, locale, and breakpoint wiring in code. Playwright or manual browser review requires a separate question and the user's direct approval for that specific check. See [testing rules](../../../../../standards/shared/testing-rules.md).
