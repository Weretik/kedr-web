# Товари — React та візуальна взаємодія

Візуальна основа: передані референси Devias Kit Pro для списку й сторінки товару. Це напрям оформлення, а не джерело полів чи дій. Зберігати наявну Admin theme: заголовок над округлою MUI Card, компактні верхні вкладки, стриману сітку з фото, схемою та основними даними, пагінацію. Форму редагування й кнопки Save/Delete з референсу не переносити.

Спільну композицію з карткою клієнта визначає [стандарт списків і деталей Admin](../../../../../standards/admin/list-detail-pages.md); тут визначено товарні поля, блоки та контракти.

- Над таблицею всередині Card: три доступні вкладки «Усі товари», «Без фото» і «На сайті» з відступом від краю, як у референсі. Під ними Data Grid із пошуком, вбудованими фільтрами й серверною пагінацією. Лічильник брати лише з `pagedInfo.totalRecords` активного режиму; не дублювати його текстом під таблицею.
- Стару окрему панель пошуку/фільтрів не повертати. Використати контрольовані `filterModel`, `sortModel`, `paginationModel`, `filterMode="server"`, `sortingMode="server"`, `paginationMode="server"`; пошук інтегрувати з Data Grid, текстовий ввід debounce. Мапер підтримує лише operator/value, наявні в API. За зміни умов або сортування page=1, стан зберігати в URL; API отримує pageIndex+1. У «Без фото» не показувати category/price range фільтрів, яких не має контракт. `rowCount` — серверний count після фільтрації.
- Застосувати українські локалі MUI Material та MUI X Data Grid на рівні Admin theme для всіх таблиць, включно з пагінацією та доступними назвами кнопок.
- У таблиці колонка «Дії» без сортування й фільтрації містить іконку ока з підказкою та accessible name. Наявність, акція, новинка й «На сайті» — окремі колонки з галочкою лише для true; для false клітинка без галочки, доступне ім'я лишається зрозумілим. Три незалежні MUI Select «Усі/Так/Ні» є в заголовках колонок наявності, акції й новинки; їхні значення з URL поєднуються в серверному запиті та скидають сторінку на першу при зміні. «На сайті» не має колонкового фільтра: окрема вкладка передає `exportToSite=true`. Фото 56 × 56 px у рядку заввишки 72 px.
- Референс Devias Kit Pro задає стриману композицію та повернення як текстове посилання зі стрілкою над заголовком; edit form/Save/Delete не переносити. Картка read-only: назва товару рівно один раз в інформаційному блоці, українська та російська назви, лише істинні ознаки як чотири різнокольорові MUI Chip без слів «Так»/«Ні», компактна таблиця «поле — значення» у цьому самому блоці. Category slug прибрати. Три окремі блоки на широкому екрані мають порядок **фото товару → основна інформація → схема товару**, якщо схема завантажилась; на телефоні й планшеті блоки переходять в одну/дві колонки за breakpoints теми та зберігають цей порядок. Обидва доступні зображення є безпосередньо клікабельними й відкриваються в MUI Dialog з accessible name, закриттям клавіатурою й поверненням фокуса. У головному блоці показувати виразну кнопку «Відкрити на сайті» лише за `exportToSite` та slug і кнопку «Сховище фото» для кожного товару. Домен storefront зберігати в конфігурації, slug URI-encode; папка фото — `https://images-kedr.cdn.express/~/o/products`. Не показувати окрему кнопку JPG під зображенням. Перевірений backend importer нормалізує ID до числа та формує `https://images-kedr.cdn.express/products/{id}.jpg`; Admin API повертає збережений `photo`. Не рендерити невдалу схему або порожній placeholder. `feature` володіє маршрутом, запитом і станами завантаження; картки, таблиця, зображення й Dialog є презентаційними компонентами `ui` та отримують дані через props.
- Спільний `AdminLayout` не показує breadcrumb на жодній сторінці. Повернення з деталей товару залишається feature-local посиланням зі стрілкою, яке зберігає query-параметри списку.
- Loading, empty, error і not found не спричиняють стрибка layout. На вузькому viewport таблиця прокручується в межах Card. Перевірити клавіатуру, focus після переходу й повернення.

Технічні перевірки: лише автоматичні component/integration tests зміненої фічі для вкладок, станів, дії та маршруту. Підключення тем, локалі й breakpoints звіряти за кодом. Playwright або ручний браузерний перегляд — тільки після окремого запитання й прямого дозволу користувача на конкретну перевірку. Див. [testing rules](../../../../../standards/shared/testing-rules.md).
