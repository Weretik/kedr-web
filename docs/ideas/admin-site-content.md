## Plan (owner approved 2026-11-04)

Each stage is one backend PR (KedrStore) and one frontend PR (kedr-web), merged only on the owner's «сливай», backend deployed first. Every stage ends with a structure check, feature cards, and focused tests.

| ----- | ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 1     | «Контакти компанії» | `content.CompanyContacts`, `GET /api/content/contacts`, admin GET/PUT                                                                                               | `/company-contacts`, all staff                           | header, footer, pages, JSON-LD, privacy placeholders                                                                            | Done 2026-11-04 (KedrStore #152, kedr-web #36) |

| 3     | «Документи»         | `content.LegalDocuments` + versions per language (offer, privacy, returns, delivery and payment); publish a new version with «Редакція від»; old versions read-only | `/documents`: list, editor (shared rich text), versions  | the four pages render the published version; `{phone}`/`{email}` placeholders stay; no fallback (500 instead of an empty offer) | Planned                                        |

| 6     | Admin polish        | «Змінено: хто, коли» on articles, contacts, requisites, documents; «Оновити сайт зараз» (on-demand revalidation through a protected site endpoint)                  | buttons and labels on the cards                          | revalidation route by cache tag                                                                                                 | Planned                                        |

Details from the first audit, kept for each stage:

- **Requisites** are money: Admin only, every change logged.
- **Documents** must be traceable: the site shows «Редакція від», old versions stay read-only.
- **Gallery** reuses the media library instead of a second image store.
- **Home blocks**: the hero stays in code (design, not content).

Not worth moving: UI labels and buttons in dictionaries (they are interface, not content), SEO title templates (rules, not texts), and the region pages (now redirected to «Співпраця»).

## Shared design

- All of it lives in the existing Content module (schema `content`), with `CanManageContent` for texts and an Admin-only policy for requisites. No new module.
- The site keeps a code fallback for contacts and requisites: if the API is down during a build or request, it uses the last values in code, so the phone never disappears. Legal documents answer 500 rather than show an empty offer.
- The site picks a change up within its cache lifetime (a few minutes), as articles do now; instant on-demand revalidation can come later.
